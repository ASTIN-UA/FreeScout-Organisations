# OrgPortal — B2B модуль управління організаціями для FreeScout

[← Back to README](../README.md)

<img src="https://raw.githubusercontent.com/ASTIN-UA/FreeScout-Organisations/refs/heads/main/Modules/OrgPortal/logo.png"  alt="OrgPortal — модуль FreeScout B2B" width="140" align="right">

**OrgPortal** — це модуль FreeScout, який додає повне **управління B2B організаціями** до вашої служби підтримки: групує клієнтів у компанії, визначає ієрархію відділів, надає корпоративним менеджерам портал самообслуговування та автоматизує сповіщення — все всередині FreeScout без зовнішніх інструментів.

> Шукаєте спосіб управління акаунтами компаній у FreeScout? Хочете дати корпоративним клієнтам свій власний портал підтримки? Контролювати, які квитки може бачити кожен B2B контакт залежно від його ролі та відділу? OrgPortal вирішує все це.

**Працює з:** FreeScout 1.8.147+  
**Опціональні інтеграції:** [End-User Portal](https://freescout.net/module/end-user-portal/), [API and Webhooks](https://freescout.net/module/api-webhooks/), [Kanban](https://freescout.net/module/kanban/), [Custom Fields](https://freescout.net/module/custom-fields/)

> [!IMPORTANT]
> **Завжди встановлюйте з [останнього релізу](https://github.com/ASTIN-UA/FreeScout-Organisations/releases/latest), а не з вихідного коду репозиторію.**
> Завантажте `OrgPortal.zip` зі сторінки Releases — він містить правильну структуру директорій, яка потрібна FreeScout.
> Завантаження вихідного коду (через "Code → Download ZIP" або `git clone`) **не працюватиме** та порушить структуру модуля.
> Автоматичні оновлення також вимагають, щоб для початкової установки використовувався ZIP-файл релізу.

## Що додає OrgPortal у FreeScout

FreeScout побудований на основі окремих клієнтів — кожен лист від людини, і немає вбудованої концепції компанії, в якій ця людина працює. Для B2C служб підтримки це добре. Для B2B це недостатньо.

OrgPortal заповнює цю прогалину:

- **Акаунти компаній** — групує клієнтів у організації з назвою, кольоровою піктограмою, обсягом поштової скрині та статусом активний/неактивний
- **Автоматичне членство за доменом електронної пошти** — прив'яжіть `company.com` до організації, і кожен клієнт, що пише з цього домена, автоматично зареєструється та буде приписаний
- **Ієрархія відділів** — розділяє організації на структурні одиниці (відділи, філіали, команди); кожен член обмежується своєю одиницею
- **Доступ на основі ролей** — `member` бачить тільки власні квитки; `unit_manager` бачить весь одиницю; `manager` бачить всю організацію
- **Портал корпоративного самообслуговування** — менеджери переглядають усі квитки компанії, відповідають, закривають, змінюють авторів та управляють налаштуваннями сповіщень без звернення до вашої команди
- **Постійна атрибуція квитків** — кожен квиток фіксується до його організації при створенні; історичні звіти зберігаються при змінах складу клієнтів
- **Багатомовні сповіщення** — автоматизовані електронні сповіщення на мові кожного менеджера з шаблонами для кожної локалізації та вбудованим редактором WYSIWYG
- **REST API** — синхронізуйте членство з вашої CRM, автоматизуйте адаптацію, керуйте тегами програмно

## Організації

*Одне місце для всього про корпоративний акаунт.*

**Керування → Організації** відкриває інтерфейс з вкладками і трьома розділами: Організації, Шаблони та Система.

### Список організацій

- **Створювати, редагувати, видаляти, активувати/деактивувати** організації
- **Фільтр статусу** — перемикання між Активні / Неактивні / Усі через групу перемикачів; фільтрує таблицю на клієнтській частині миттєво
- **Пошук в реальному часі** — починає фільтрувати при 2+ символах без перезавантаження сторінки
- **Кольорові піктограми** — інтерактивна палітра кольорів з 12 зразків та попередній перегляд піктограми поруч із селектором; піктограма з'являється на кожному квитку та карті Kanban
- Клік на піктограму або кількість квитків відкриває пошук FreeScout, відфільтрований за організацією
- **Прив'язка поштової скрині** — організації можуть бути глобальними (усі поштові скрині) або обмежені конкретною поштовою скринею
- **Колона тегів** — показує ✓/✗ чи прив'язані якісь теги FreeScout до організації (потрібен модуль Tags); теги призначаються у формі редагування з допомогою віджету на основі мікросхем та автозаповнення
- **Колона кількості квитків** — всього розмов на організацію; посилання, яке клікається на повні результати пошуку
- **Колона кількості членів**
- **Активувати / деактивувати** — призупинити акаунт без втрати історії; вимагає активацію Org Snapshot (кнопка деактивована з підказкою коли це не так)
- **Видалити** — доступно тільки коли організація має 0 членів та 0 квитків (механізм безпеки)
- Всі дії видалення та деактивації вимагають підтвердження

![Organizations list](https://raw.githubusercontent.com/ASTIN-UA/FreeScout-Organisations/main/docs/screenshots/org-list.png)

### Форма редагування організації

- **Назва** та **прив'язка поштової скрині**
- **Палітра кольорів** — 12 зразків із попереднім переглядом піктограми
- **Теги** — віджет на основі мікросхем: вводьте для пошуку існуючих тегів FreeScout, клікайте для додавання, × для видалення
- **Таблиця членів** — для кожного члена: ім'я, роль, структурна одиниця, прапорець `can_manage_org` (надає доступ адміністратора до організацій без повних прав адміністратора), перемикач активний/неактивний
- **Панель структурних одиниць** — створюйте та перейменовуйте одиниці безпосередньо у формі редагування; члени призначаються одиницям у тому ж представленні
- **Додавання члена** — автоматично заповнює існуючі неатрибульовані розмови для цього клієнта

![Organization edit](https://raw.githubusercontent.com/ASTIN-UA/FreeScout-Organisations/main/docs/screenshots/org-edit.png)

### Інтеграція з профілем клієнта

- **Поле організації у формі редагування клієнта FreeScout** — пошук організацій з автозаповненням в реальному часі; випадаюче меню ролей з'являється після вибору організації; кнопка × для видалення
- **Посилання швидкого доступу "Переглянути квитки організації"** у формі клієнта
- **Блок інформації про організацію на бічній панелі адміністратора** — назва організації (посилання, яке можна клікати на сторінку редагування організації), структурна одиниця та роль члена; перемикання видимості для кожної поштової скрині в налаштуваннях
- **Одне активне членство на клієнта** — клієнт не може бути доданий до другої організації поки має активне членство; неактивні/архівовані членства дозволені

## Структурні одиниці — контроль доступу на рівні відділу

*Підтримуйте великі підприємства зі складними внутрішніми ієрархіями.*

Організації можна розділити на необмежену кількість **структурних одиниць** (відділи, філіали, регіональні офіси, проектні команди):

- Створюйте, перейменовуйте та видаляйте одиниці у формі редагування організації адміністратора або безпосередньо з портала (тільки глобальні менеджери)
- Призначайте членів одиницям — кожен член належить до однієї одиниці
- **Видалення одиниці** автоматично понижує членів `unit_manager` до `member`

**Три рівні ролей:**

| Роль | Обсяг доступу |
|------|-------------|
| `member` | Тільки власні квитки |
| `unit_manager` | Усі квитки в межах їх структурної одиниці |
| `manager` (глобальний) | Усі квитки на всю організацію |

- Менеджери одиниці мають повні можливості портала — відповіді, вкладення, змінення авторів, закриття/повторне відкриття, управління сповіщеннями — обмежені суворо межами їх одиниці
- Доступ до квитків та доставка сповіщень застосовуються на межах одиниці

## Домени електронної пошти — Автоматичне членство

*Припиніть додавати персонал однієї компанії одного за одним.*

Прив'яжіть домен електронної пошти до організації, і кожен клієнт, що пише з цього домена, буде приписаний до неї та автоматично зареєстрований як член — ніякого ручного кроку, ніяких забут, коли вперше пише нова людина.

Налаштовується в межах організації в **Керування → Організації → Редагування → Домени електронної пошти**.

### Як працює відповідність

| Правило | Поведінка |
|--------|----------|
| **Тільки точна відповідність** | `company.com` відповідає `jane@company.com`. Він **не** відповідає `jane@mail.company.com` або `jane@www.company.com` — додайте їх як окремі записи, якщо хочете |
| **Нормалізація** | `@Company.COM`, `https://www.company.com/` та `company.com.` зберігаються як `company.com` |
| **Ручна атрибуція завжди перемагає** | Клієнт, який уже належить до іншої організації, ніколи не переміщується. Контрактори та навмисні рішення адміністратора в безпеці |
| **Відозвання залишається** | Деактивування члена є постійним, поки людина його не скасує. Клієнт може продовжувати надсилати електронні листи; автоматизація не відновить його доступ |
| **Область поштової скрині** | Домен в організації, що залежить від поштової скрині, застосовується лише в межах цієї поштової скрині. Прив'язування до поштової скрині має пріоритет над глобальною для того ж домена |
| **Кілька доменів** | Організація може мати стільки доменів, скільки їй потрібно (`company.com`, `company.co.uk`, придбаний бренд…) |

### Публічні провайдери блоковані

`gmail.com`, `outlook.com`, `ukr.net`, `icloud.com`, послуги тимчасової пошти та подібні **відхиляються під час збереження**. Прив'язування одного потягне сотні непов'язаних клієнтів в одну організацію і — через End-User Portal — дасть їм доступ до квитків один одного.

Список постачається з модулем і може бути **розширений** (ніколи не скорочений) через опцію `orgportal.public_domains_extra` для регіональних провайдерів. Жорстко закодована резервна копія гарантує, що основні провайдери залишаються заблокованими навіть якщо конфігураційний файл відсутній або пошкоджений.

Деактивовані організації повністю припиняють реєстрацію клієнтів.

### Додавання існуючих клієнтів

Нова прив'язка впливає лише на майбутню пошту. Щоб зареєструвати клієнтів, які вже існують, прив'язка впливає лише на майбутню пошту: клієнти, які вже існують, не реєструються ретроактивно. Вони беруться, коли напишуть знову.

### Видалення прив'язки

Видалення домена зупиняє майбутнє автоматичне приписування. Члени, яких він уже створив, **зберігаються за замовчуванням** — вони, можливо, вже використовують портал. Вас окремо запитують, чи хочете ви їх деактивувати; це відкочування торкається лише членів, зареєстрованих цим конкретним доменом, ніколи тих доданих вручну.

Члени, створені автоматично, позначені **@** значком у списку членів.

## Org Snapshot — постійна атрибуція квитків

*Надійна історична звітність навіть при змінах вашого складу клієнтів.*

Коли квиток створюється, OrgPortal записує контекст організації як постійний знімок:

- `org_id`, `org_unit_id` та `org_attributed_at` записуються до розмови при створенні
- **Незмінний** — якщо клієнт пізніше залишає організацію, його історичні квитки залишаються атрибульовані до цієї організації; звітність ніколи не порушується
- **Додавання члена** запускає автоматичне заповнення існуючих неатрибульованих розмов цього клієнта

### Джерело атрибуції — три режими

Налаштовується у **Керування → Організації → вкладка Система**:

| Режим | Поведінка |
|------|----------|
| `member` | Атрибулювати квиток організації членом якої є автор квитка |
| `tag` | Атрибулювати за тегом FreeScout прив'язаним до організації спочатку; повернутися до членства якщо тег не збігається |
| `tag_only` | Атрибулювати виключно за тегом; членство не використовується |

Режими `tag` та `tag_only` деактивовані коли модуль Tags неактивний.

**Домени електронної пошти діють як останній засіб** у режимах `member` та `tag`: коли ні прив'язка до тега, ні існуюче членство не розв'язує квиток, перевіряється домен електронної пошти автора. Він ніколи не переважує жодну з них, тому правило тега або ручна атрибуція адміністратора завжди має пріоритет. У режимі `tag_only` відповідність доменів не використовується.

### Інструменти заповнення

- **Смуга прогресу** — показує X / Y квитків атрибульовані (%) з індикатором "завершено" коли готово
- **Статистика перевірки** — перед запуском заповнення порівняння показує скільки квитків буде атрибульовано за тегом vs членством vs неузгоджені
- **Кнопка запуску заповнення** — обробляє до 2000 квитків за клік; результат підсумку (by_tag / by_member / unmatched) показується після
- **Авто-cron** (`attribution_cron_enabled`) — планує заповнення кожні 5 хвилин, 1000 квитків за запуск без перекриття
- **Скинути атрибуцію** — очищає усі знімки організацій (дія небезпеки вимагає підтвердження)
- Командний рядок: `php artisan orgportal:backfill-attribution`

## End-User Portal — самообслуговування для корпоративних менеджерів *(опціонально)*

*Дайте вашим B2B клієнтам портал де вони керують своїм компанійним відношенням підтримки — без звернення до вашої команди для кожного оновлення статусу.*

Вимагає модуль [End-User Portal](https://freescout.net/module/end-user-portal/).

### Панель керування квитками компанії

Виділений розділ **Company Tickets** у навігації портала з повнофункціональною таблицею квитків:

| Колона | Опис |
|--------|------|
| **#** | ID квитка |
| **Subject** | Усічена з підказкою при наведенні |
| **Responsible** | Призначена агента підтримки |
| **Author** | Клієнт який відкрив квиток; клік для фільтрування за цим автором |
| **Status** | Активний / Чекаючий / Закритий / Спам з іконками |
| **State** | Назва колони Kanban на поточній мові портала (тільки коли модуль Kanban активний) |
| **Updated** | Дата та час останньої відповіді |

**Два незалежні індикатори статусу прочитання на рядок** — це відслідковують двох різних людей та показуються одночасно:

| Індикатор | Чий статус прочитання | Що це означає |
|-----------|----------------------|---------------|
| **Жирний рядок** | Менеджер який переглядає портал | Менеджер має непрочитані сповіщення для цієї розмови — щось сталось чого вони ще не бачили |
| **👁 Іконка ока** | Автор квитка (клієнт який його відправив) | Автор ще не відкрив останню відповідь агента — корисно для того щоб знати чи клієнт насправді побачив відповідь |

Ці два стани повністю незалежні: рядок може бути жирним (менеджер не прочитав) а око відсутнє (автор вже прочитав), або навпаки. Менеджер бачить обидва одночасно, даючи повну картину того що відбувається з обох сторін квитка без його відкриття.

**Фільтр автора** — клік на ім'я автора активує фільтр; банер з'являється у верхній частині таблиці показуючи активне ім'я автора з посиланням × для очищення фільтра.

Як таблиця робочого стола так й адаптивний **макет карток для мобільних** включені; вони автоматично переходять залежно від ширини екрана.

Шаблон смуги фільтра підтримує **перевизначення** через `enduserportal::partials.tickets_filters` — розмістіть кастомне представлення за цим шляхом щоб замінити мову OrgPortal за замовчуванням збереігаючи усю функціональність.

![Company Tickets](https://raw.githubusercontent.com/ASTIN-UA/FreeScout-Organisations/main/docs/screenshots/portal-tickets.png)

### Дії з квитками у портала

Менеджери можуть вживати дій безпосередньо — немає потреби звертатись до підтримки:

- **Відповідь з вкладеннями** — перетягніть & розташуйте, декілька файлів на відповідь; назви вкладень та розміри файлів показуються на кожній гілці
- **Закрити квиток** — нова відповідь автоматично його відкриває; банер інформує менеджера про це коли квиток закритий
- **Змінити автора квитка** — перепризначити квиток до іншого члена організації
- **Фільтрувати по одиниці** — глобальні менеджери фільтрують список квитків за структурною одиницею
- **Фільтрувати по статусу Kanban** — налаштовується для кожної поштової скрині, мітки показуються на поточній мові портала

## Підписки на сповіщення *(опціонально)*

*Дайте менеджерам вирішити що вони слухають — не більше не менше.*

- **Матриця підписки** на вкладці "Сповіщення" в параметрах організації портала
- **Три типи подій:** Новий квиток · Відповідь агента · Відповідь клієнта
- **Два рівні обсягу:** Вся організація (глобальні менеджери) · Окремі структурні одиниці
- Члени без одиниці групуються в окремий рядок **"No unit"** розширюваний
- **Перевизначення для кожного члена** — розширіть будь-який рядок одиниці щоб виявити окремих членів та перемикайте їх підписи внутрішньо; менеджери одиниці з обмеженою роллю позначені відповідно
- **Логіка каскадного каскаду в обох напрямах:**
  - Активація "Вся організація" → активує усі одиниці та усіх членів
  - Активація одиниці → активує усіх її членів
  - Деактивація члена → авто-узгоджує флажки одиниці та організації
- Глобальні менеджери керують усіма членами; менеджери одиниці керують тільки своєю одиницею
- Сповіщення використовують драйвер пошти відповідної поштової скрині

## REST API *(опціонально)*

*Інтегруйте OrgPortal у вашу CRM, ERP або робочий процес адаптації клієнтів.*

Вимагає модуль [API and Webhooks](https://freescout.net/module/api-webhooks/).

- Повна CRUD для організацій, структурних одиниць, членства клієнтів та тегів
- **Поля організацій:** `name`, `color`, `mailboxId`, `isActive` — усі читаються та оновлюються через API
- **Піддієструса членів** — `GET/PUT/DELETE /api/organizations/{id}/members/{memberId}` — оновіть роль, одиницю, `canManageOrg` та окремий `isActive` прапорець члена незалежно без торкання решти членства
- **Піддієструса тегів** — `GET/PUT /api/organizations/{id}/tags` — список або повне заміна прив'язок тегів (вимагає модуль Tags; повертає `503` якщо неактивний)
- Автентифікація через заголовок `X-FreeScout-API-Key` або параметр запиту `api_key`
- Інтерактивна **документація ReDoc** на **Керування → API & Webhooks → OrgPortal API Docs** (`/orgportal/admin/api-docs`)

📖 **Full API reference → [docs/api/README.md](docs/api/README.md)**

1. Завантажте `OrgPortal.zip` з [останнього релізу](https://github.com/ASTIN-UA/FreeScout-Organisations/releases/latest)
2. Розпакуйте та скопіюйте папку `OrgPortal` у `Modules/` вашої установки FreeScout
2. Перейдіть до **Керування → Модулі → OrgPortal → Активувати**
3. Запустіть міграції:
   ```bash
   php artisan module:migrate OrgPortal
   ```
4. Очистіть кеш:
   ```bash
   php artisan cache:clear && php artisan config:clear
   ```

> **Підтримка грузинської мови** розгортується автоматично при першому завантаженні — копіювання файлів вручну не потрібно.

## Автоматичні оновлення

OrgPortal підтримує **оновлення одним кліком** через вбудований механізм оновлення модулів FreeScout.

> **Вимагає FreeScout 1.8.170 або пізніше.** На старіших версіях оновіть вручну замінивши папку `OrgPortal` на найновішу версію ZIP.

Коли доступна нова версія банер з'являється на **Керування → Модулі**. Клікніть **Оновити зараз** — FreeScout завантажить та встановить найновішу версію автоматично.

## Конфігурація

### Глобальні налаштування — **Керування → Організації → вкладка Система**

| Опція | Опис |
|-------|------|
| Показати піктограму на сторінці квитка | Піктограма організації у списку розмов та представленні квитка |
| Показати піктограму на карточках Kanban | Піктограма організації на карточках дошки Kanban |
| Джерело атрибуції | `member` / `tag` / `tag_only` — як квитки атрибулюються до організацій |
| Авто-cron заповнення | Запускати заповнення кожні 5 хвилин автоматично |
| Видимість знімка | Показувати/приховувати дані атрибуції у бічній панелі квитка |
| Селектор мови портала | Активувати селектор мови у панелі навігації EUP; вибрати які з 19 локалізацій пропонувати |

### Налаштування для кожної поштової скрині — **Налаштування поштової скрині → OrgPortal**

Перевизначає глобальні значення для конкретної поштової скрині.

| Опція | Опис |
|-------|------|
| Показати піктограму на сторінці квитка | Активувати/деактивувати піктограму для цієї поштової скрині |
| Показати піктограму на карточках Kanban | Активувати/деактивувати піктограму для цієї поштової скрині |
| Показати блок організації в профілі клієнта | Перемикання блоку інформації організації у бічній панелі квитка |
| Фільтри статусу квитків компанії |映射 стовпців Kanban на названі фільтри у портала; мітки для кожної мови з селектором локалізації; перетягніть для переупорядкування |

## Переклади

OrgPortal повністю локалізований у **19 мовах**:

| Мова | Код | Мова | Код |
|------|------|------|------|
| English | `en` | Dutch | `nl` |
| Ukrainian | `uk` | Norwegian | `no` |
| German | `de` | Danish | `da` |
| French | `fr` | Swedish | `sv` |
| Spanish | `es` | Finnish | `fi` |
| Italian | `it` | Portuguese (BR) | `pt-BR` |
| Czech | `cs` | Portuguese (PT) | `pt-PT` |
| Slovak | `sk` | Romanian | `ro` |
| Polish | `pl` | Chinese Simplified | `zh-CN` |
| Georgian | `ka` | | |

Файли перекладів: `Modules/OrgPortal/Resources/lang/{locale}/messages.php`

Шаблони електронних сповіщень мають вбудовані за замовчуванням для усіх 19 мов.

### Інтеграція селектора мови

OrgPortal включає вбудований селектор мови портала (активуйте у **вкладці Система → Селектор мови портала**). Також він інтегрується з [EUP Switch Language](https://freescout.net/module/eup-sw-lang/) — обидва можуть бути активні одночасно.

Мова яку менеджер вибирає застосовується до усіх рядків UI OrgPortal та зберігається як їх мова сповіщень — листи відправляються на їх вибрану мову автоматично.

> **Технічна нотатка:** `OrgPortalSetLocale` мідлвера переповторює локалізацію портала після мідлвери FreeScout `Localize` щоб запобігти її скиданню у системний за замовчуванням на кожному запиті.

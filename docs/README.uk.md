# OrgPortal — Портал організацій для FreeScout

<img src="../Modules/OrgPortal/logo.png" alt="OrgPortal" width="140" align="right">

Модуль для FreeScout, що додає поняття **Організацій** (компанії/команди) до клієнтів, розширює End-User Portal для менеджерів і відображає плашку організації на тікетах та картках Kanban.

**Мінімальна версія FreeScout:** 1.8.147  
**Залежності:** немає обов'язкових  
**Опціональні:** [End-User Portal](https://freescout.net/module/end-user-portal/), [API and Webhooks](https://freescout.net/module/api-webhooks/), [Kanban](https://freescout.net/module/kanban/)

## Можливості

### Управління організаціями (адмін)
- **Manage → Organizations** — повний CRUD: створення, редагування, видалення організацій
- **Прив'язка до поштової скриньки** — організація може бути **глобальною** (видна в усіх скринькам) або **прив'язаною до конкретної скриньки**; відповідна мітка відображається в списку організацій
- Призначення клієнтів до організацій з вибором ролі: `member` або `manager`
- **Зміна ролі учасника** прямо в таблиці (без видалення та повторного додавання)
- Автодоповнення пошуку клієнтів за іменем або email; клієнти, які вже в якій-небудь організації, виключаються з результатів
- Email учасника відображається під іменем у таблиці членів
- Один клієнт — одна організація (застосовується на рівні БД та API)
- **Колір плашки** — візуальна палітра з 12 кольорів в формі редагування організації; за замовчуванням сірий

### Права доступу користувача
- Нове право **"Дозволено керувати організаціями"** — користувачі без прав адміністратора з цим правом отримують доступ до списку, створення та редагування сторінок організацій
- Нове право **"Дозволено керувати шаблонами сповіщень"** — окремо від управління організаціями, дозволяє редагувати шаблони email-сповіщень
- Видалення організацій залишається виключним правом адміністраторів

### Картка клієнта
- Поле **Організація** у формі редагування клієнта — виберіть організацію та роль
- Кнопка **Заявки організації** — відкриває пошук усіх тікетів організації

### Плашка організації на тікетах
- Відображається під темою на сторінці тікета та перед іменем у списку розмов
- Клікабельна — відкриває пошук усіх тікетів цієї організації
- Колір плашки визначається параметром організації (за замовчуванням сірий)
- Увімкнення/вимкнення **по скриньці** через **Параметри скриньки → OrgPortal**; глобальне значення використовується як резервне

### Плашка організації на картках Kanban
- Відображається після лічильника повідомлень на кожній карті
- Клікабельна — веде до пошуку організації
- Колір відповідає параметру організації
- Фільтр **Організація** вбудований у стандартне розкривне меню фільтру Kanban: модальне вікно з прапорцями, подібне до фільтру тегів; стан зберігається між навігаціями
- Увімкнення/вимкнення **по скриньці** через **Параметри скриньки → OrgPortal**

### Фільтр пошуку організацій
- Розширює стандартний пошук FreeScout фільтром **Організація**
- Показує всі тікети клієнтів, які належать до вибраної організації

### End-User Portal — доступ менеджерів *(опціонально)*

Менеджер організації отримує розширений доступ через EUP:

- Елемент **Тікети компанії** в навігації портала
- Таблиця тікетів компанії зі стовпцями:
  - **#** та **Тема** з відсіканням еліпсису та підказкою при наведенні
  - **Відповідальний** — призначений агент
  - **Автор** — клієнт, який відкрив тікет; клік фільтрує тікети за автором в межах організації
  - **Статус** — Активний / Очікування / Закритий / Спам з піктограмами
  - **Стан** — ім'я колони Kanban (з користувацькою міткою, якщо налаштована); показується тільки якщо модуль Kanban активний
  - **Оновлено** — дата та час останньої відповіді
- Пошук за темою тікета
- Фільтри за статусами Kanban (налаштовуються через **Параметри скриньки → OrgPortal**)
- Відповідь на тікет з підтримкою **вкладень** (перетягування, кілька файлів)
- **Закриття тікета** — менеджер може закрити тікет; нова відповідь автоматично його відкриває
- Зміна автора тікета — переназначення тікета іншому члену організації
- Сторінка **Параметри організації** для налаштування email-сповіщень
- Доступ до тікетів **строго обмежено поточною скринькою** (організація скопійована в іншу скринь­ку — портал 403)

### Підписки на сповіщення *(опціонально)*

Менеджери портала можуть налаштувати, які подій та сфери дії запускають email-сповіщення:

- **Матриця підписки** на вкладці "Сповіщення" в параметрах організації портала
- **Події:** Новий тікет, Відповідь агента, Відповідь клієнта
- **Сфери дії:** Вся організація (тільки для глобальних менеджерів) або конкретні структурні одиниці
- **Каскадна поведінка:** Позначення "Вся організація" автоматично позначає всі рядки одиниць; зняття позначення будь-якої одиниці знімає позначення "Вся організація"
- Сповіщення використовують поштовий драйвер відповідної скриньки

### Email-сповіщення *(опціонально)*
- Використовує поштовий драйвер відповідної скриньки
- Шаблони email-сповіщень можуть налаштовуватися адміністраторами (див. розділ нижче)

### Шаблони email-сповіщень *(опціонально, потребує права "Дозволено керувати шаблонами сповіщень")*

Адміністратори можуть налаштовувати шаблони email на вкладці **Шаблони сповіщень** сторінки **Manage → Organizations**.

**Типи шаблонів:**
- Сповіщення про новий тікет
- Сповіщення про відповідь агента
- Сповіщення про відповідь клієнта

**Можливості:**
- WYSIWYG редактор Summernote для кожного шаблону
- Засіб вибору змінних-макросів для вставки доступних заповнювачів
- Залишіть шаблон порожнім, щоб використовувався вбудований шаблон за замовчуванням

**Доступні змінні-макроси:**
| Змінна | Опис |
|--------|------|
| `{manager_name}` | Ім'я менеджера, який отримує сповіщення |
| `{author_name}` | Ім'я автора тікета (клієнта, який створив/відповів) |
| `{org_name}` | Назва організації |
| `{unit_name}` | Назва структурної одиниці (якщо застосовується) |
| `{subject}` | Тема тікета |
| `{ticket_number}` | ID тікета |
| `{ticket_url}` | Посилання на тікет у портальній панелі |
| `{created_date}` | Дата створення тікета (формат: YYYY-MM-DD) |
| `{created_time}` | Час створення тікета (формат: HH:MM:SS) |
| `{created_datetime}` | Дата і час створення тікета (ISO 8601) |
| `{reply_date}` | Дата відповіді (формат: YYYY-MM-DD) |
| `{reply_time}` | Час відповіді (формат: HH:MM:SS) |
| `{reply_datetime}` | Дата і час відповіді (ISO 8601) |

### Параметри скриньки

**Параметри скриньки → OrgPortal** (по скриньці):

| Опція | Опис |
|-------|------|
| Показувати плашку на сторінці тікета | Увімкнення/вимкнення плашки в межах цієї скриньки |
| Показувати плашку на картках Kanban | Увімкнення/вимкнення плашки в межах цієї скриньки |
| Фільтри статусу тікетів компанії | Виберіть колони Kanban, відображені як прапорці на сторінці тікетів; користувацька мітка для кожного фільтру |

### REST API *(опціонально, потребує API та Webhooks)*

OrgPortal надає повноцінний REST API для керування організаціями, структурними підрозділами та членством клієнтів — автентифікація через заголовок `X-FreeScout-API-Key` або параметр запиту `api_key`.

📖 **Повний довідник API → [docs/api/README.uk.md](api/README.uk.md)** (усі ендпоінти, приклади запитів/відповідей, коди помилок)

Інтерактивна документація ReDoc також доступна в **Manage → API & Webhooks → OrgPortal API Docs** (`/orgportal/admin/api-docs`).

## Установка

1. Скопіюйте папку `OrgPortal` в `Modules/` вашого FreeScout
2. В адмін-панелі: **Manage → Modules → OrgPortal → Activate**
3. Запустіть міграції:
   ```bash
   php artisan module:migrate OrgPortal
   ```
4. Очистіть кеш:
   ```bash
   php artisan cache:clear && php artisan config:clear
   ```

## Оновлення

OrgPortal підтримує **автоматичні оновлення** через вбудований механізм оновлення модулів FreeScout.

> **Потребує FreeScout 1.8.170 або новіше.** На старіших версіях банер оновлення не з'явиться — оновіть модуль вручну, замінивши папку `OrgPortal` з останнього релізного ZIP.

Коли доступна нова версія, баннер з'явиться на сторінці **Управління → Модулі**. Натисніть **Оновити зараз** — FreeScout завантажить і встановить найновішу версію автоматично.

Копіювання файлів вручну не потрібно.

Файли: `Modules/OrgPortal/Resources/lang/{locale}/messages.php`

### EUPSWLANG інтеграція

Модуль коректно працює з [EUP Switch Language](https://freescout.net/module/eup-sw-lang/): мова, вибрана в портале, також застосовується до рядків OrgPortal.

Щоб мова з'явилася в списку EUPSWLANG, відповідний файл `Modules/EndUserPortal/Resources/lang/{locale}.json` повинен існувати. Файли для **Română** (`ro`) включені в пакет; **Georgian** (`ka`) підтримується тільки в адмін-частині (немає системної підтримки в ядрі FreeScout).

> **Технічна деталь:** middleware `ReapplyEupLocale` (зареєстрована останньою в групі портальних маршрутів) відновлює localize після middleware `Localize` FreeScout, яке інакше би скинуло мову портала на системне значення за замовчуванням.
